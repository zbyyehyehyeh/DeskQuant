# DeskQuant 汇率与币种方案

> 记录「回测 vs 模拟盘」的汇率处理区别、汇率源优先级、以及 quote vs time_series 的历史深度。

## 1. 回测 vs 模拟盘：汇率处理区别

| 场景 | 时间轴 | 汇率用法 | 说明 |
| --- | --- | --- | --- |
| 回测 | 历史 bar，按时间归并，多策略同一条时间轴 | **一个当前汇率**套到整段回测 | 不做逐 bar 历史汇率对齐（简化，够用） |
| 模拟盘 | 实时行情 | **实时当前汇率** | 天然匹配，随行情一起走 |

- 两者都用 `globalFxRates()`（内存里的当前汇率），差别只在「回测用一个快照、模拟盘持续刷新」。
- 结论：回测用单一当前汇率、模拟盘用实时汇率，**当前实现是自洽的**。

## 2. 汇率源优先级（准确度优先，只存内存）

汇率源**与「数据源模式」（国内/国外）无关**：无论选国内还是国外数据源，汇率都按下面顺序**由程序根据网络可达性自动选择**，不受用户选择控制——只要连得上新浪就用新浪（真实中间价），连不上才逐级降级。

1. **新浪财经（中国服务器，全球可直连）**：`hq.sinajs.cn`，实时中间价，免费无 key —— **始终首选**，回测/模拟盘都用它。
2. **Twelve Data**：实时，带 key —— 新浪连不上时兜底。
3. **open.er-api**：日更，免费无 key —— 最终兜底。

- 汇率**不落盘**，用到时（启动 / 切换币种）当场请求，结果存内存 `globalFxRates()`。
- 顶部汇率栏显示当前用的源 + 该源的限制（+ Twelve Data 剩余次数）。

## 3. quote vs time_series（历史深度）

| 接口 | 用途 | 历史 |
| --- | --- | --- |
| `quote` | 实时快照 | 只有当前价，无历史 |
| `time_series` | 历史 OHLC | 单次最多 **5000 根**，可配 `start_date`/`end_date` |

5000 根对应的时间跨度（取决于 interval）：

- `1day`：约 **20 年**（外汇日线历史足够）
- `1h`：不到 1 年
- `1min`/`5min`：几天到几周，且免费档分钟级历史通常只给最近一段

> 当前回测**不需要历史汇率**（用单一当前汇率），所以只用 `quote`。以后若要「回测逐日对齐历史汇率」，日线用 `time_series` 一次拉 20 年即可；分钟级历史汇率免费档给不深。
